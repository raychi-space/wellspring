# 图片上传、预览与发布权限 v0.1

日期：2026-09-28。状态：基础上传、私密读取和随发布快照变化的授权已实现；此文同时保留尚需验证的编辑器交互要求。

## 1. 已确认的体验

管理台采用同一区域所见即所得编辑，不需要跳到公开站预览草稿。第一版必须支持直接粘贴图片，自动上传后原位置显示图片，保存时序列化为 Markdown 图片链接；未发布的图片对访客不可访问，站长登录后可以在编辑区查看。

编辑流程：粘贴图片 → 原位置显示上传占位及进度 → 后端持久保存并返回地址 → 原位置显示图片 → 保存时序列化为 `![图片说明](地址)` → 保存工作稿 → 明确发布后公开渲染 Markdown 及图片。

图片上传成功不代表文章已经保存或发布。上传时光标移动、同时粘贴多图都不能让返回结果插错位置或覆盖用户新输入；占位位置被删除时不再插回。失败可以重试或移除，尚未完成的上传不能作为成功图片保存或发布。上传完成但未插入/未保存的文件保持私密，后续再处理孤立文件清理。

## 2. 地址与权限分开

Markdown 持久保存稳定的、同源相对路径：

```markdown
![示例截图](/api/v1/public/assets/22222222-2222-4222-8222-222222222222/content)
```

这只是内容地址，不是访问凭证。首次发布前，任何人直接访问此公开地址都得到 404，包括已登录站长；管理台预览时将受管理的图片地址解析为对应的 `/api/v1/admin/assets/{assetId}/content`，由会话授权读取。这个替换仅发生在预览渲染层，不修改保存的 Markdown。

两个前端都通过各自同源 `/api` 代理连接 wellspring。私密图片请求不依赖 Markdown 中嵌入 token、Cookie 或临时签名；管理台退出或会话过期后停止展示私密预览，新读取要求重新登录。

首版每张图片归属于一篇文章，暂不支持跨文章共享托管附件。上传新图永远生成新 assetId，不覆盖旧图片字节；否则修改工作稿时可能提前改变已发布页面中的图片。

## 3. 附件与发布快照的关系

服务端维护 Asset 元数据：`id`、`articleId`、内部 `storageKey`、经验证的 `mediaType`、`byteSize`、宽高、创建时间和文件就绪状态。内部存储路径不返回前端。

工作稿与发布快照分别记录所引用的 assetId 集合。后端从 Markdown 语法树中的图片引用（含引用式语法）及封面字段解析关联，不信任客户端传来的“已发布附件列表”，也不把代码块里的示例链接算作图片引用。

公开读取必须同时满足：文件存在且就绪、所属文章当前为 PUBLISHED、图片被该文章当前发布快照的正文或封面引用。仅仅“属于一篇已发布文章”不够。

| 操作 | 访客能够访问的图片 |
| --- | --- |
| 新建草稿，粘贴 A 并保存 | 无；站长在管理台可以看 A |
| 发布含 A 的版本 | A |
| 已发布文章工作稿新增 B，尚未再发布 | A；B 仍为 404 |
| 工作稿删除 A，尚未再发布 | A 仍随旧公开版本可读 |
| 再发布只含 B 的新版本 | B；A 的新公开读取返回 404 |
| 撤回文章 | A、B 的新公开读取均返回 404；站长仍可预览 |
| 上传 C 但没有插入文章，随后发布文章 | C 始终不可公开访问 |

发布事务一起切换文章快照、正文与封面引用集合、状态及版本；失败时保留旧快照和旧权限。撤回以文章状态立即阻止新的公开读取，不依赖异步任务把文件挪到另一个目录。物理文件始终在私有存储中。

保存/发布时，引用不存在、未就绪或属于其他文章的托管图片返回 `400 ASSET_REFERENCE_INVALID`，不静默生成坏图。复制别篇文章的托管链接须重新上传到当前文章。用户手写外链图片的公开权限由外部站点控制，此处隐私保证针对 Raychi 上传并托管的图片。

## 4. 最小接口

| 方法 | 路径 | 约定 |
| --- | --- | --- |
| POST | `/api/v1/admin/articles/{id}/assets` | 会话＋CSRF；multipart/form-data 的 `file` 字段；201 返回元数据与地址 |
| GET / HEAD | `/api/v1/admin/assets/{assetId}/content` | 站长会话；200 图片字节/响应头；未登录 401，不存在 404 |
| GET / HEAD | `/api/v1/public/assets/{assetId}/content` | 仅当前发布快照中的图片可读；不可见与不存在统一 404，Cookie 不扩大权限 |

上传成功响应示例：

```json
{
  "id": "22222222-2222-4222-8222-222222222222",
  "articleId": "11111111-1111-4111-8111-111111111111",
  "url": "/api/v1/public/assets/22222222-2222-4222-8222-222222222222/content",
  "previewUrl": "/api/v1/admin/assets/22222222-2222-4222-8222-222222222222/content",
  "mediaType": "image/png",
  "byteSize": 184320,
  "width": 1280,
  "height": 720
}
```

正文只存 `url`，`previewUrl` 服务于管理台显示层。编辑器图片节点保留稳定地址，显示层解析为私密预览地址；不能把显示层 DOM 中的认证地址重新序列化进正文。Markdown 序列化时转义图片说明中的特殊字符，文件名不作为可执行文本拼接。

上传占位通过编辑器事务/节点映射跟踪，在异步返回时更新仍存在且属于该文档的节点；不以过期字符串下标插入 Markdown。撤销、删除占位或切换文章后不得插错图片。完整要求见[编辑器约定](../../../inkwell/docs/editor-v0.1.md)。

新文章首次保存或粘贴前，管理台先确保存在服务端草稿 ID。创建接口允许空工作稿，缺省 slug 由后端生成唯一的 `draft-<uuid>`；发布前要求真实标题及有效正文，站长可在首次发布前编辑 slug。图片上传本身不改变文章 version 或发布快照，随后保存 Markdown 时才按文章乐观锁规则写入引用。

当前实现支持 PNG、JPEG，单文件上限 10 MiB、解码像素上限 1600 万。服务端验证实际文件内容与类型，不只看扩展名或客户端 MIME；拒绝 SVG/HTML、畸形文件和超限图片。超限返回 413 `ASSET_TOO_LARGE`，不支持或损坏的图片返回 400 `ASSET_INVALID`。WebP 可在后续加入。

文件先完整落到私有持久目录并形成就绪元数据，再返回成功。写文件或写元数据失败时不返回可用地址；中断产生的临时/孤立文件不能被公开访问。数据库元数据和实际图片文件一起备份，容器重建后仍保留。

## 5. 防止直链和缓存绕过

- 不把图片放进前端 `public/`、Nginx 可直接访问目录或公开对象桶；请求必须经过 wellspring 的权限判断。私有目录与鉴权读取符合 [OWASP 文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) 的存储与权限建议。
- 第一版所有图片读取和失败响应使用 `Cache-Control: no-store`；Nginx/CDN/应用代理不缓存这些路径，直接透传鉴权后的结果，不跳转到可绕过权限的存储地址。
- 两前端用原生 `img` 直接读取相应图片端点，不经过 Next.js 图片优化缓存。若其他图片启用优化器，也必须排除/拒绝本系统附件路径及其后端地址，验证手写 `/_next/image` URL 无法为附件建立旁路缓存。Next.js 官方文档说明默认优化器不转发认证头，且优化图片缓存没有通用失效机制；据此暂不用于需即时撤回的附件。[Next.js Image 文档](https://nextjs.org/docs/app/api-reference/components/image)
- GET、HEAD 和将来支持的 Range/条件请求执行相同权限判断；不得通过响应头、304 或缩略图旁路暴露私密附件。首版不必实现 Range、条件缓存或缩略图端点。
- 撤回和替换约束的是后续向系统发起的读取；先前已下载或已开始传输的图片无法远程收回。首次发布之前不得向访客发送图片字节。

## 6. 集成验收

用已登录管理台和独立无痕访客会话执行上方状态表，检查图片直链而不仅检查页面是否隐藏。至少覆盖：首次粘贴建草稿、上传失败重试、多图异步完成顺序、发布前私密预览、对已发布文章新增图片、仅删除工作稿引用、更新发布移除旧图、撤回、HEAD、优化器旁路及重启后的持久化。以真实存储、数据库和 HTTP 请求为证据。
